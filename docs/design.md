## A. Domain 선정 — 도메인과 문제 정의

### A.1 왜 AgTech 인가
**정책 수요는 분명하고 투자는 선별적이다.** 그래서 '유망해 보이는 기업'과 '투자할 만한 기업'을 근거로 가르는 평가가 이 분야에서 특히 쓸모 있다.

| 근거 | 내용 |
|---|---|
| <span style="white-space:nowrap">정책</span> | 「스마트농업 육성 및 지원에 관한 법률」(2024 시행)과 제1차 스마트농업 육성 기본계획(2025~2029)으로 정책 수요가 분명하다 |
| <span style="white-space:nowrap">투자 흐름</span> | 2025년 글로벌 애그리푸드테크 투자는 162억 달러로 전년과 비슷했고(-3%, 후기 투자자는 신중) 한국은 크게 늘었다(AgFunder, 2026). 2~3년 전 과열 뒤 조정 국면이라 **옥석 가리기**가 중요하다 |
| <span style="white-space:nowrap">현장 문제</span> | 농가 고령화·인력난·기후 리스크로 자동화 수요는 크지만, 농가 ROI·다작기 실증·자본집약도의 벽에 막혀 실패한 스타트업도 많다 |

### A.2 문제 정의
> **국내외 비상장 AgTech AI 스타트업(Seed~Series C, Exit 전)을 공개 정보로 발굴·검증하고, 투자를 받은 동종 기업의 평균과 비교해 투자 추천 여부를 가린 뒤, 임원이 30초 안에 '할까요, 말까요'를 정할 수 있는 5쪽 이내 보고서를 만든다.**

**문제 범위와 조건**

| 항목 | 설계 |
|---|---|
| <span style="white-space:nowrap">선별 원칙</span> | 조정 국면을 전제로, 투자를 받은 동종 기업보다 **근거가 뚜렷이 앞서는 기업**만 투자 추천한다 |
| <span style="white-space:nowrap">평가 분야</span> | AI·센서·로봇으로 농업 **생산성**을 높이는 기업. 가이드 도메인 문구('작물 재배, 병해충 진단, 수확 등')에 맞춰 세부 분야 5개로 나눈다: ① 스마트팜·시설원예 AI 환경제어 ② 작물 생육·병해충 진단 AI ③ 농업 로봇·자율주행 농기계 ④ 축산 AI(가축 건강·사양 관리) ⑤ 농업 생산 데이터 분석·예측 AI (생육·환경 데이터) |
| <span style="white-space:nowrap">스타트업 조건</span> | 과제 조건 그대로: 비상장(코스피·코스닥 제외) · 투자 단계 Seed~Series C · M&A 등 Exit 미완료 |
| <span style="white-space:nowrap">조사 지역</span> | 국내외. 발굴 라운드마다 적격성 검증 자리를 국내 12곳 + 해외 6곳으로 나눠, 해외 후보가 순서에 밀려 빠지지 않게 한다 |
| <span style="white-space:nowrap">산출물</span> | A안: 투자 추천 기업의 평가 보고서(가이드 주제 '투자 가능한 스타트업에 대한 평가 보고서'). B안: 모두 보류면 루프를 끝내고 후보마다 '왜 안 되는지'와 '무엇이 확인되면 되는지'로 구성. C안: 적격 후보가 없을 때(E장) |

**성공 기준(평가 계획)**

| 대상 | 지표 | 측정·판정 방법 |
|---|---|---|
| 검색기 | Hit@4 · MRR@4 | RAG 문서로 만든 평가 질문에서 임베딩 후보를 비교해 가장 높은 설정을 채택한다(B.5) |
| <span style="white-space:nowrap">RAG 답변</span> | Relevance · Faithfulness · Correctness(이진, 질문 20개) | 답변마다 질문에 답했는지, 인용한 근거로 뒷받침되는지, 정답과 맞는지를 예/아니오로 판정한다(B.4) |
| <span style="white-space:nowrap">적격성 관문</span> | 판정 정확도 | 상장·Exit·투자 단계를 아는 기업으로 잰다. 가이드의 제외 예시(배달의민족 M&A Exit, 루닛·뷰노 코스닥 상장)는 모두 탈락해야 한다 |
| <span style="white-space:nowrap">결정 규칙</span> | 합성 대조 | 결론이 분명한 가상 후보(예: 모든 문항 미확인 → 보류)로 규칙이 의도대로 판정하는지 확인한다(C.4) |
| <span style="white-space:nowrap">보고서 형식</span> | 형식 검사 | 5쪽 이내, SUMMARY 반쪽 이내, REFERENCE 지정 형식을 모두 지켜야 한다 |
| 재현성 | 재실행 비교 | 저장해 둔 검색 결과·LLM 응답으로, 새로 받은 저장소에서 API 키 없이 같은 보고서가 나와야 한다 |

## B. 설계

### B.1 에이전트 정의
에이전트는 가이드 정의(안) 6개에 👤 창업자 평가 1개를 더한 **7개**로 둔다. 가이드 6개는 이름·역할을 그대로 쓰고, 가이드의 '설계 목적에 따라 추가/변경 가능' 조항에 따라 하나만 추가한다. 원칙은 **1 에이전트 = 1 Scorecard 기준 = 1 State 키**다. 각 에이전트는 자기 기준의 근거 수집부터 판정까지 혼자 끝낸다.

**에이전트 7개의 책임·판정 기준·State 키**

| 에이전트 (노드) | 한 가지 책임 | 판정 기준 | RAG | 주요 도구 | 쓰는 State 키 |
|---|---|---|---|---|---|
| 🔍 스타트업 탐색 (`discover`) | 평가할 **다음 적격 스타트업 1곳**을 정한다. 내부 3단계: 발굴 → 적격성 관문 G1~G6 → 다음 후보 선택 | — (평가 전 관문) | O — 문서 속 기관 선정 기업(교정형 검색) | 웹 검색, TIPS 목록·투자 기사 피드, 상장 목록 대조, 국민연금 사업장 | current, queue, screened, seen, raw_candidates, discovery_rounds, iterations, end_reason |
| 👤 창업자 평가 (`founder`) **— 추가** | 창업 시점(t0)을 먼저 고정하고, 창업 **전** 전문성과 창업 **후** 실행력을 나눠 판정 | 창업자 30% (F1~F4) | X — 사람에 관한 사실은 문서 코퍼스에 없음 | 웹 검색(인터뷰·기사), 기사 원문 수집, 국민연금 조회 결과(첫 고용·인원) | founder |
| 🗜️ 기술 요약 (`tech`) | 핵심 기술·장단점을 요약하고, 경쟁사 비교가 검증할 **차별점 주장**을 정리 | 제품/기술력 15% (P1~P4) | O — 분야 기술 기준선(논문·보고서) | 문서 요약(홈페이지·기사), Agentic RAG, 웹 검색 | tech |
| 📊 시장성 평가 (`market`) | 세부 분야의 시장 크기·성장·수요(실제 문제·지불 의향) | 시장성 25% (M1~M4) | **O (주 사용처)** — 하위 질문 3~6개마다 Agentic RAG | Agentic RAG, 웹 검색 | market, market_cache |
| 🥊 경쟁사 비교 (`competition`) | 같은 제품 유형의 국내외 경쟁사와 비교하고, 기술 요약의 차별점 주장을 검증 | 경쟁 우위 10% (C1~C4) | X (가이드 표 그대로) | 웹 검색, 기사 속 경쟁사 추출 | competition |
| 🧮 투자 판단 (`decide`) | 실적·투자조건을 판정하고 6개 기준을 **종합**(동종 대비 배수). 리스크(Deal-killer)·ROI·후보 리스트를 곁들여 **투자/보류** 결정 | 실적 10%·투자조건 10% (R1~R4, D1~D4) | X — 문항별 원문 인용 대조(RAG 아님) | 규칙 기반 판정, 인용 대조 | scorecard, decision, evaluations, end_reason |
| 📝 보고서 생성 (`report`) | **단계별 결과를 장마다 연결**해 5쪽 이내 PDF를 만들고 형식을 검사. 새로 조사하지 않음 | — | X | 템플릿·PDF 렌더러·REFERENCE 포맷터 | report |


**가이드 안과 달라지는 점**

1. **👤 창업자 평가를 추가한다.** 창업자는 Scorecard 에서 비중이 가장 큰 기준(30%)이다. 교수님은 링크드인 팔로워 방식을 두고 "이 양반이 언제 창업했는지가 중요"하다고 짚으며 새 창업자 평가 방식을 요청했다. 기술 요약은 기술만, 창업자 평가는 사람만 맡는다.
2. **탐색은 에이전트 하나, 내부 3단계로 둔다.** 발굴(많이 찾기)과 적격성 관문(정확히 거르기)은 탐색 에이전트 안의 단계다. 메인 그래프에서는 Graph(안)처럼 한 노드이고, 보류가 나오면 이 노드로 돌아온다.
3. **실적·투자조건은 투자 판단이 직접 판정한다.** 가이드 역할 '종합 판단(리스트, ROI 등)'에 맞춰 재무·거래 조건 판정과 6개 기준 종합을 한 에이전트가 책임진다.

### B.2 도구 정의
도구는 **LLM 이 상황에 따라 고르는 도구**와 **정해진 단계에서 항상 호출하는 결정적 도구**로 나눈다. 기준은 '같은 입력에 늘 같은 답이 나와야 하는가'다.

- **LLM 이 고르는 도구**: LangChain 도구로 정의해 이름·입력·설명(용도·한계·최신성)을 LLM 에 넘긴다. Agentic RAG 안에서 LLM 이 질문마다 **문서 검색과 웹 검색 중 하나를 고른다**(D.4).
- **결정적 도구**: 상장 여부·국민연금 가입 이력 같은 사실 확인은 LLM 판단 없이 공개 자료와 규칙으로 대조한다.
- **문서 요약**: LangChain 도구로 정의하되, 요약 대상(회사 홈페이지·기사)이 정해져 있으므로 기술 요약 에이전트가 직접 호출한다.

**도구 7개의 목적·호출 방식**

| 도구 (입력) | 가이드 목적 | 호출 방식 | 사용 에이전트 | 외부 키 |
|---|---|---|---|---|
| 문서 검색 (질의) | PDF 자료 기반 정보 추출 | LLM 선택 (Agentic RAG) | 기술 요약·시장성 | 없음 (로컬 KURE-v1·FAISS·Kiwi BM25) |
| 웹 검색 (질의, 최근 우선 여부) | 외부 정보 검색 | LLM 선택 + 에이전트 직접 호출 | 탐색·창업자·기술·시장성·경쟁사 | Serper·Tavily (같은 질의는 캐시 재사용) |
| 문서 요약 (대상 문서, 요약 초점) | 문서 요약 | 에이전트 직접 호출 | 기술 요약: 홈페이지·기사 → 핵심 기술·장단점 (홈페이지를 못 읽으면 기사 본문) | OpenAI (gpt-4.1-mini) |
| 상장 목록 대조 (KRX KIND) | 스타트업 기준 '비상장' | 결정적 | 탐색 (관문 G1) | 없음 |
| 국민연금 사업장 조회 | 창업 시점(첫 고용)·인원·탈퇴 | 결정적 | 탐색 (관문 G4), 창업자 평가 (t0·고용 추이) | 없음 |
| TIPS 목록·투자 기사 피드 | 발굴 채널 | 결정적 | 탐색 (발굴) | 없음 |
| 기사 원문 수집 | 근거 본문·게시일 확보 | 결정적 | 탐색 (관문 근거 보강), 창업자·기술 (본문 발췌) | 없음 |

- **최신성**: 웹 검색은 최근 1년 결과를 우선 가져오고, 결과가 부족할 때만 기간 제한을 푼다. 교수님은 프롬프트를 대충 쓰면 옛날 자료가 올라온다고 경고했다. 사건 날짜가 평가일 기준 24개월 안인지는 LLM 에 맡기지 않고 날짜 규칙으로 다시 확인한다.
- **출처 신뢰도**: 개인 블로그·커뮤니티·SNS·주가 시세·유료 시장조사 홍보 페이지 48개 도메인은 근거에서 제외한다. 검색 기간·제외 도메인·결과 수는 설정 파일에 두고 코드에 고정하지 않는다.

### B.3 스타트업 탐색 전략
탐색 에이전트는 **발굴 → 적격성 관문 → 다음 후보 선택** 3단계로 평가 대상 1곳을 정한다(흐름도는 D.3).

- 대기열에 적격 후보가 남아 있으면 발굴 없이 바로 다음 후보를 꺼낸다.
- 대기열이 비면 검색 표현을 바꿔 다시 발굴한다(최대 2라운드). 그래도 없으면 '후보 소진'으로 보고서 단계에 넘긴다.

**발굴은 창업자(링크드인)가 아니라 회사에 일어난 '날짜가 찍힌 공개 사건'으로 한다.** 교수님 지적대로 링크드인 팔로워 같은 지표는 가입한 날부터 쌓여 **창업 시점과 맞지 않는다.** 개인 경력은 회사의 창업 시기·투자 단계·상장 여부도 알려 주지 않고, 로그인·약관 문제로 재현도 어렵다.

**발굴 채널과 선택 이유**

| 채널 | 무엇을 주나 | 왜 유효한가 |
|---|---|---|
| T. TIPS 창업기업 공개 목록 | 설립일·선정연도·운영사 | 운영사가 먼저 투자해야 선정 → **Seed 급 투자 이력 보장** |
| W. 투자 기사 피드 (와우테일 애그테크) | 투자 유치 기사·게시일 | 라운드 자체가 정확한 게시일과 함께 기사화됨 |
| A. 투자 유치 뉴스 (세부 분야 5개) | 시드·시리즈 라운드 | 단계·시점이 함께 잡힘 |
| B. 공공 선정 (A-벤처스, 스마트농업 우수기업) | 정부가 검증한 기업 | 초기 기업 풀 |
| C. 스타트업 DB 스니펫 | 설립일·투자 단계 | 직접 크롤링하지 않음(robots·차단 정책 준수) |
| D. 수상·전시, E. 문서 RAG, F. 해외 투자 뉴스 | 보완 채널 | 국내 후보가 부족할 때 확장 |
| **국민연금 가입 사업장 내역** (공공데이터, 키 불필요) | 최초 가입일·가입자 수·탈퇴 여부 | **회사의 창업(첫 고용) 시기와 실제 인원**을 제3자 공공자료로 확인. 탈퇴면 폐업·휴업 신호(G4) |
| **기사 원문 수집** (키 불필요) | 근거 기사 본문·원문 게시일 | 스니펫에 없는 창업자 이력·실적·계약 확보, 게시일을 원문 메타데이터로 보정 |

- **교차 신호**: 서로 다른 채널에서 함께 잡힌 후보일수록 실재하고 활발한 기업으로 보고 우선순위를 올린다.

**창업자 평가도 창업 시점(t0)에 맞춘다.**

1. t0 을 먼저 고정한다. 우선순위는 TIPS 공개 목록의 설립일 → 국민연금 사업장 최초 가입일(첫 고용) → 관문에서 확인한 설립연도(같은 연도의 원문 설립 표현이 있으면 그 근거를 붙임) → 근거 속 가장 이른 설립 표현이다. 어느 값을 썼는지 보고서에 적는다.
2. 창업 **이전** 경력만 전문성(F1)으로 인정한다.
3. 창업 **이후** 성과는 날짜가 찍힌 사건(수상·선정·투자·출시) 중 평가일 기준 24개월 안의 것만 실행력(F3)으로 인정한다.

**적격성 관문 G1~G6**

| 관문 | 통과 조건 | 확인 방법 |
|---|---|---|
| <span style="white-space:nowrap">G1 비상장</span> | 상장 목록에 없음 | 한국거래소 KIND 상장 목록과 규칙으로 대조, 해외는 뉴스 근거 |
| <span style="white-space:nowrap">G2 투자 단계</span> | 최근 투자 단계 Seed~Series C | 한 인용문에 '회사명+단계'가 함께 있을 때만 인정 |
| <span style="white-space:nowrap">G3 Exit 없음</span> | 인수·경영권 이전·상장 완료 근거 없음('추진'은 통과) | 인수·상장 반증 검색 |
| <span style="white-space:nowrap">G4 존속</span> | 최근 24개월 회생·파산·폐업·사업 중단·구조조정·창업자 이탈·분쟁·제재 근거 없음 | 반증 검색 + 국민연금 사업장 탈퇴 여부 |
| <span style="white-space:nowrap">G5 분야</span> | AI 가 핵심이고 농업 생산성 기술 | 두 조건 모두 '예'일 때만 통과. 유통·중개·배달·수산 양식·식품 가공, 상장사·대기업 계열 제외 |
| <span style="white-space:nowrap">G6 근거</span> | 회사명이 나오는 서로 다른 출처 3곳 이상, 제3자 1곳 이상 | 근거마다 회사명 포함 여부와 출처(회사 자체·제3자) 구분 |

- **확인 못 하면 통과시키지 않는다(fail-closed)**: 상장 목록을 못 불러오거나 검증·반증 검색이 실패하면 '확인 불가'로 탈락시키고, 보고서 한계점에 회사별로 적는다.
- **루프**: 투자 판단이 보류면 메인 그래프가 탐색으로 돌아와 다음 후보를 받는다(Graph(안)의 E→A). 상한은 발굴 2라운드, 심층 평가 10곳(반 공용 API 키의 비용 상한이자 교수님이 모든 루프에 두라고 한 '최대 반복 횟수')이다. 상한 때문에 평가하지 못한 적격 후보는 보고서에 이름을 밝힌다.

**적격성 관문 평가 계획**

| 항목 | 계획 |
|---|---|
| 정답 라벨 | 30개사. 관문 조정용 20개사(국내 9·해외 11, 적격 11·부적격 9)와 조정에 쓰지 않는 홀드아웃 10개사(해외, 적격 5·부적격 5)로 나눈다 |
| 라벨 근거 | 공개 기사·기업 DB. 회사마다 판정 근거 문장을 함께 적는다. 사람의 독립 검수는 두지 않으므로 한계로 밝힌다 |
| 지표 | 적격/부적격 이진 판정의 정확도·정밀도·재현율. 가이드의 제외 예시(배달의민족·루닛·뷰노)는 모두 탈락해야 한다(A.2) |
| 우선순위 | 거짓 양성(부적격 회사 통과)을 가장 무거운 오류로 본다. 심층 평가 비용을 쓰고 보고서 신뢰를 잃기 때문이며, fail-closed 원칙과 같은 방향이다 |
| 과적합 점검 | 관문 규칙은 조정용 20개사로만 고치고, 홀드아웃 10개사 결과로 일반화를 확인한다 |
| 오류 분석 | 틀린 회사마다 어느 관문(G1~G6)에서 틀렸는지 기록해 다음 수정 대상으로 삼는다 |

### B.4 RAG 적용 대상과 문서 선정 전략
**RAG 는 가이드 표에서 'O'인 세 에이전트(탐색·기술 요약·시장성)에 모두 적용한다.** 'X'인 경쟁사 비교·투자 판단·보고서 생성과 가이드에 없는 창업자 평가는 벡터 검색을 쓰지 않는다. 가이드의 최소 조건('O 중 1개 이상')보다 넓게, 표의 O/X 를 그대로 따르는 것이 RAG 적용 대상 선정의 근거다. 투자 판단이 문항마다 후보 근거에서 원문 인용을 찾는 단계는 RAG 가 아니라 **인용 대조**로 구분한다.

**에이전트별 RAG 적용 방식**

| <span style="white-space:nowrap">에이전트</span> | 묻는 질문 | 방식 | 이유 |
|---|---|---|---|
| <span style="white-space:nowrap">탐색</span> | 기관이 선정·평가한 국내외 AgTech 기업과 투자 사례(기업명 포함) | 교정형 검색만(검색 → 이진 채점 → 재작성 → 웹 보완), 답변 생성 없음 | 목적이 기업명 추출이므로 조각을 LLM 개체 추출에 넘긴다 |
| <span style="white-space:nowrap">기술 요약</span> | {세부 분야}의 기술 성숙도·상용화 수준·기술적 과제 | Agentic RAG(D.4) → 인용 달린 기준선 답변 | 가이드 문구 '홈페이지, 논문 등에서 핵심 기술, 장단점' 중 '논문' 부분 |
| <span style="white-space:nowrap">시장성</span> | 시장 크기·성장률·수요/지불 의향·정책·도입 장벽·투자 사이클 | 하위 질문 3~6개로 분해 → 하위 질문마다 Agentic RAG | 시장 수치는 공신력 있는 문서가 필요하고, 웹에는 유료 시장조사 홍보 수치가 섞인다 |

**답변 품질 평가 계획(LLM-as-a-Judge, 이진 판정)**: 평가 질문 20개에 대해 Relevance·Faithfulness·Correctness 를 O/X 로 판정한다. Generator·Judge 가 모두 gpt-4.1-mini(공용 키 비용 때문에 mini 등급)라 자기 답을 후하게 볼 수 있다. 이를 보완하려고 평가표 판정에 쓰는 인용문은 원문에 실제로 있는지 문자열 대조로 확인하고, 적격성 판정은 B.3 의 정답 라벨(30개사)과 대조한다.

**문서 선정 원칙**: ① 공공기관·연구기관·동료심사 논문. 예외로 **AgFunder 2026(민간 투자 리포트, 65쪽)**을 포함한다. 글로벌·국가별·단계별 AgTech 투자 추이를 연 단위로 주는 공개 자료가 이것뿐이다 ② 2023년 이후 ③ 최종본만, **발췌 없이 문서 전체** ④ 후보 기업이 많은 세부 분야(로봇·시설원예·축산)에 기술·사업성 문서 배치 ⑤ 이해상충 문서 제외(후보 기업 소속 연구소장이 쓴 보고서)

**웹 검색 기간 규칙**: 투자·실적·경쟁 뉴스는 최근 1년을 먼저 찾고, 부족하면 기간 제한을 푼다. 설립·인수·폐업처럼 과거 사건은 기간 제한 없이 찾는다. 평가 문항은 사건 날짜로 다시 거른다(실적·투자·시장 성장 문항은 평가일 기준 24개월).

- **범위보다 적합성**: 벡터DB 에 문서를 많이 넣는다고 결과가 좋아지지 않는다(교수님 강조). 196쪽을 에이전트 질문에 맞춰 고르고, 검색 범위를 넓히는 대신 질문마다 문서·웹 중 출처를 고르게 한다(D.4).
- **전처리**: 매 페이지 머리글·바닥글 제거 · **출처·각주 줄을 본문에서 분리**(출처 줄의 날짜를 사건 날짜로 잘못 읽을 위험을 막는다) · 2단 편집은 단 순서로 읽기 · 표는 캡션과 묶어 별도 조각 · 참고문헌 페이지 제외 · 조각 800자 / 겹침 100자
- **검색**: Kiwi 형태소 BM25 + Dense 하이브리드(RRF) → 검색기마다 후보 8개 → Judge LLM 관련성 O/X → 검색 순위대로 앞 4개. 임베딩과 가중치는 B.5 선정 실험으로 정한다.

### B.5 임베딩 모델 선정 (후보·기준·선정 실험)
**임베딩은 리더보드 순위가 아니라 우리 문서로 만든 질문 70개의 검색 성능으로 고른다.** 가이드도 '리더보드 상위 랭크'는 적절한 선택 이유가 아니라고 하며, 공개 한국어 검색 벤치마크에서 상위 모델 간 차이는 nDCG@10 1.5%p 이내(KURE 공개 벤치마크)라 문서 종류에 따라 순위가 바뀔 수 있다. 임베딩은 RAG 설계의 결정 사항이므로, 에이전트 개발에 앞서 검색 단계만 떼어 설계한 검색 설정(후보 8개 → 상위 4개) 그대로 사전 선정 실험을 한다.

**경제성(과제 문구의 첫 단어)**: 후보는 모두 오픈소스이고 GPU 없는 노트북 CPU 에서 돌아가므로 임베딩 API 비용이 0원이다. 문서·질의 임베딩은 한 번만 계산해 캐시하므로 재실행·재현에 추가 비용이 없다.

**후보 선정 기준**

| 기준 | 이유 | 판정 |
|---|---|---|
| C1 한·영 혼용 | 한국 보고서 + 영문 보고서 코퍼스 | 한국어 검색 학습 또는 다국어 검색 학습 |
| C2 최대 길이 ≥ 조각 길이 | 800자 한국어 조각은 최대 약 700토큰 | 128토큰 모델은 조각이 모두 잘려 제외 |
| C3 노트북 재현성 | 팀원 노트북, GPU 없음 | GPU 없이 동작, 문서 임베딩은 한 번만 계산해 캐시 |
| C4 라이선스 | 오픈소스 조건, 결과 공개 | MIT/Apache 명시(미기재 모델 제외) |
| C5 입력 규칙 위험 | 접두어를 빠뜨리면 조용히 성능 저하 | 규칙을 설정 파일에 명시 |

**최종 비교 후보 6개**: bge-m3(다국어 기준선) · KURE-v1(bge-m3 한국어 미세조정) · snowflake-arctic-embed-l-v2.0-ko(한국어 미세조정) · multilingual-e5-large(평균 풀링 계열 대조군) · Qwen3-Embedding-0.6B(디코더 기반 대안) · multilingual-e5-small(저사양 대안). 제외: ko-sroberta·MiniLM(128토큰 한계, 검색용 아님), upskyy/bge-m3-korean(라이선스 미기재), BGE-m3-ko(KURE 와 같은 가설, 학습 데이터 미기재).

**평가 질문**: 코퍼스에서 만든 질문 70개(자연어형 40 + 키워드형 30), 정답은 근거가 있는 같은 문서·같은 페이지다. 1차 실험은 임베딩 6종을 Dense·BM25·하이브리드 조합으로 재고, 임베딩마다 MRR@5 최고 조합을 싣는다.

**사전 선정 실험 1차: 임베딩 6종 × 검색 방식**

| 검색 방식      | 임베딩                        |   Hit@1 |   Hit@3 |   Hit@5 |   MRR@5 |
|:---------------|:---------------------------------|--------:|--------:|--------:|--------:|
| Dense          | nlpai-lab/KURE-v1                |   0.800 |   0.938 |   0.971 |   0.868 |
| Dense          | snowflake-arctic-embed-l-v2.0-ko |   0.771 |   0.954 |   0.971 |   0.864 |
| Dense          | BAAI/bge-m3                      |   0.734 |   0.929 |   0.958 |   0.831 |
| Dense          | Qwen/Qwen3-Embedding-0.6B        |   0.704 |   0.904 |   0.942 |   0.803 |
| Dense          | multilingual-e5-large            |   0.684 |   0.850 |   0.866 |   0.763 |
| Kiwi BM25      | -                                |   0.600 |   0.675 |   0.721 |   0.644 |
| Hybrid 0.5:0.5 | multilingual-e5-small            |   0.542 |   0.729 |   0.729 |   0.624 |

**2차 실험 기준**: 1차 실험은 Judge LLM 이 후보 8개를 다시 거른다고 보고 8개 안 적중(Hit@8)을 중시하며, 그 기준의 1차 후보는 snowflake-arctic-ko + 하이브리드 0.3:0.7 이다. 그러나 답변 근거는 관련 조각 중 **검색 순서대로 앞 4개만** 쓰므로, 2차 실험은 **Hit@4(앞 4개 안 적중)와 MRR@4** 로 재고 선택 규칙을 측정 전에 정한다(표의 한국어/영어는 정답 문서의 언어, 질문은 모두 한국어). ① 전체 Hit@4 가 가장 높은 설정 ② 같으면 MRR@4 가 높은 설정 ③ 다른 임베딩이 1위여도 1차 후보 임베딩의 최고 설정이 두 지표 모두 0.01 이내면 1차 후보 유지.

**사전 선정 실험 2차: 후보 8개 → 앞 4개**

| 설정 (후보 8개) | Hit@1 | Hit@3 | **Hit@4** | **MRR@4** | Hit@8 | 한국어 문서 Hit@4 | 영어 문서 Hit@4 |
|---|---|---|---|---|---|---|---|
| snowflake + 하이브리드 0.3:0.7 (1차 후보) | 0.700 | 0.929 | 0.943 | 0.808 | 0.971 | 1.000 | 0.852 |
| snowflake Dense | 0.771 | 0.957 | 0.971 | 0.865 | 0.971 | 1.000 | 0.926 |
| snowflake + 하이브리드 0.5:0.5 | 0.586 | 0.900 | 0.929 | 0.736 | 0.986 | 1.000 | 0.815 |
| KURE-v1 Dense | 0.800 | 0.943 | 0.943 | 0.864 | 0.986 | 0.953 | 0.926 |
| KURE-v1 + 하이브리드 0.3:0.7 | 0.700 | 0.957 | 0.986 | 0.826 | 0.986 | 1.000 | 0.963 |
| **KURE-v1 + 하이브리드 0.4:0.6 (선택)** | 0.714 | 0.957 | 0.986 | 0.833 | 0.986 | 1.000 | 0.963 |
| KURE-v1 + 하이브리드 0.5:0.5 | 0.586 | 0.929 | 0.957 | 0.752 | 0.986 | 1.000 | 0.889 |
| Kiwi BM25 단독 | 0.586 | 0.657 | 0.686 | 0.624 | 0.700 | 0.953 | 0.259 |

- **결과**: **KURE-v1 + 하이브리드 0.4:0.6** 이 Hit@4 0.986(70문항 중 69), MRR@4 0.833 으로 1위다. 1차 후보(snowflake 0.3:0.7)는 Hit@4 0.943 으로 3문항을 더 놓친다. snowflake 의 최고 설정(Dense 단독, Hit@4 0.971)도 규칙 ③의 0.01 범위 밖이므로 임베딩을 KURE-v1 으로 정한다.
- **가중치 민감도**: KURE-v1 하이브리드는 BM25 0.1~0.4 에서 Hit@4 가 모두 0.986 이고 MRR@4 차이도 0.013 이내라, 특정 가중치 하나에 기대는 결과가 아니다. 0.5:0.5 는 영어 문서의 1위 적중(Hit@1)이 0.148 로 떨어져 가장 나쁘다. 가중치보다 임베딩 선택의 효과가 크다.
- **하이브리드를 쓰는 이유**: 같은 KURE-v1 에서 Dense 단독은 Hit@4 0.943 이다. BM25 가 회사명·정책명처럼 정확한 용어가 든 키워드형 질문을 보완한다(키워드형 Hit@4 0.900 → 1.000).
- **한계**: 질문 70개라 1문항 차이가 0.014 다. 질문은 LLM 으로 만들고 거르며 사람이 전수 검수하지 않으므로 한계로 밝힌다. 차이가 작으므로 개발 단계에서 평가 질문을 늘려 선정 결과를 다시 확인한다.

## C. 투자 판단 기준 (평가표)

### C.1 두 표준의 역할 — 무엇을 묻고, 어떻게 합칠까
가이드의 두 표준을 역할을 나눠 함께 쓴다. Scorecard 는 기준을 합치는 방법을, Bessemer 체크리스트는 판정할 질문을 맡는다. 과제 설명은 둘 중 하나를 고르는 것과 섞어 쓰는 것을 모두 허용하며, 평가표는 개발 단계에서 그대로 규칙으로 옮길 수 있도록 문항·요건·계산식까지 정한다.

**두 표준의 역할 분담**

| 표준 | 맡는 일 | 적용 위치 |
|---|---|---|
| **Scorecard** (가이드 표 + Bill Payne) | **어떻게 합칠까.** 가이드 표의 6개 기준·가중치(창업자 30·시장성 25·제품/기술력 15·경쟁 우위 10·실적 10·투자조건 10)에 Payne Scorecard 의 **'평균 기업 = 100%' 비교 원리**를 더한다 | 배수 계산(C.3), 결정 규칙(C.4) |
| **Bessemer 체크리스트 10문** | **무엇을 물을까.** 24개 판정 문항의 출처이자 보고서의 10문 점검표 | 판정 문항(C.2), 점검표(C.5) |

- Payne 원 방법(ACA 2019)은 요인이 7개이고 가중치도 다르다. 가이드 표의 6개 기준·가중치는 그대로 두고, 원 방법에서는 '투자를 받은 평균 기업과 비교한다'는 원리만 가져온다.
- 세부 문항에는 AgTech 투자에서 반복되는 실패 요인(농가 ROI·다작기 실증·인허가·자본집약도·보조금 의존)을 넣는다. 근거는 코퍼스 문서(USDA 정밀농업 도입·로봇 착유 수익성, 수직농장 경제성 논문, 스마트농업 기본계획)다.

### C.2 판정 문항 (24개, 이진 판정)
**판정 방식**: 1~5점 척도 대신 **YES / NO / 미확인**으로 판정한다(N/A 는 인허가 문항 P4 만). '애매하면 이진으로 판정하고 척도 판정은 신중히 하라'는 강의 권고를 따르며, 척도(배수)는 LLM 이 매기지 않고 C.3 공식으로 계산한다.

- YES 는 근거 원문 인용이 있어야 한다. 인용문이 실제 근거 본문에 있는지 문자열로 대조하고, 없으면 미확인으로 내린다.
- NO 도 반대 사실을 적은 문장의 인용이 있어야 한다. '근거가 없다'는 NO 가 아니라 미확인이다(없음과 반대를 구분).
- 회사 고유 문항은 인용 앞뒤 300자 안에 **회사명**이, 성능·경제성 문항은 **제3자 근거**가(대표 발언·회사 계획은 제3자 근거가 아님), 실적·투자·시장 성장 문항은 **최근 24개월** 근거가 있어야 한다.
- '상용화 예정·실증·시범 운영'은 상용 운영이 아니다. 투자 금액이 '비공개'면 라운드 문항(D1)을 인정하지 않는다.
- LLM 에는 점수·기준점을 보여 주지 않고 **기준마다 따로** 판정시킨다(후광 효과 방지).
- 각 기준은 그 기준을 맡은 에이전트가 자기 단계까지 모인 근거로 판정한다. 실적·투자조건과 앞 단계에서 판정되지 않은 기준은 투자 판단이 판정한다. 판정 규칙과 프롬프트는 하나로 두고 모든 담당 에이전트가 함께 쓴다.

### C.3 점수 — 동종 투자 유치 기업 대비 배수
점수는 절대 점수가 아니라 **동종 투자 유치 기업 평균 = 100** 에 대한 배수로 매긴다.

**절대 점수를 쓰지 않는 이유**

- 강의에서 Scorecard 는 비중을 둔 '100점 기준' 점수로 설명되었으므로 보고서도 100 을 기준으로 적는다. 다만 **100 은 만점이 아니라 동종 평균이며, 투자 기준은 110 이다.**
- Payne Scorecard 는 대상 기업을 '같은 지역·단계에서 투자를 받은 평균 기업'과 비교해 기준마다 %(평균 = 100%)를 매기고 비중대로 더한다. '70점 이상' 같은 절대 컷은 원 방법에 없고, 임의로 정한 컷으로는 임원의 고정 질문 "평가 기준이 뭐예요? 임의대로 하셨나요?"에 답할 수 없다.
- 미확인을 0점으로 두는 절대 점수는 공개 정보의 양을 사업의 질로 읽는다. 공개 정보가 적은 초기 기업은 일률적으로 낮은 점수가 되어, 실제로 투자를 받은 기업까지 보류로 판정될 수 있다.

**계산 절차**

1. **문항 신호 x**: YES = +1, NO = −1, 미확인 = 0 (N/A 는 빼고 계산)
2. **동종 평균 x̄**: 적격성 관문을 통과해 같은 절차로 평가한 후보(최대 10곳)의 문항별 평균 신호. 모두 관문 G2 에서 투자 유치가 원문 인용으로 확인된 AgTech 기업이지만 단계(Seed~Series C)와 지역(국내·해외)이 섞여 있어, **원 방법의 '같은 지역·단계 투자 유치 기업'의 근사**다. 이 차이는 한계로 적는다(C.8, 보고서 한계점).
    - 본 평가 전에 기준 집단을 따로 판정하는 보정 절차를 두고, 문항별 x̄ 를 기준 집단 파일로 고정한다.
    - 평가 대상이 기준 집단에 있으면 **자기 자신을 뺀 평균**(leave-one-out)을 쓴다.
    - 기준 집단이 5곳 미만이면 x̄ = 0(미확인 = 평균이라는 가정)으로 계산하고, 보고서에 '설계 가정'이라고 표기한다.
3. **기준별 비교율**: **c_d = clip(1 + 0.5 × mean(x_q − x̄_q), 0.5, 1.5)** — 한 기준의 문항이 모두 동종 평균보다 한 단계 앞서면 150%, 뒤지면 50%.
4. **Scorecard 배수**: **M = Σ w_d × c_d** (w = 0.30 / 0.25 / 0.15 / 0.10 / 0.10 / 0.10). 동종 평균 = 1.00. 보고서에는 '동종 평균 대비 113 (평균 100, 기준 110)'처럼 쓴다.

> 예: 창업자 4문항이 YES·YES·미확인·NO 이고 동종 평균 x̄ 가 0.5·0.2·0.3·−0.1 이면, 차이의 평균 = (0.5 + 0.8 − 0.3 − 0.9) ÷ 4 = 0.025 → c = 1 + 0.5 × 0.025 = 1.0125. 창업자 기준은 동종 평균의 101% 다.

**미확인의 뜻**: 미확인은 0점이 아니다. **동종 기업이 평균적으로 공개하는 만큼에 못 미친 차이만** 감점된다.

- 동종 기업 대부분이 공개하지 않는 문항(예: Seed~A 기업의 매출 R1)은 x̄ 가 0 에 가까워, 미공개여도 감점이 거의 없다.
- 동종 기업 대부분이 공개하는 문항(예: 기관투자자 참여 D2)은 못 찾으면 그만큼 불리하다.
- 모든 기업이 YES 인 문항(예: 시장 규모 M1)은 차이가 0 이 되어 변별 점수를 주지 않는다.

실제 후보를 평가하기 전에 가상 기업 두 곳으로 계산식을 점검한다.

**합성 대조 점검 (통과 기준)**

| 가상 기업 | 통과 기준 | 확인하는 것 |
|---|---|---|
| 모든 문항 미확인 | M < 1.10 → 보류 | 정보를 감춘 회사가 유리해지지 않음 |
| 모든 문항 YES | M ≥ 1.10 → 투자 추천 | 근거가 모두 확인되면 기준을 넘음 |

### C.4 결정 규칙 (사전 고정)
> **투자 추천 ⇔ M ≥ 1.10 ∧ 창업자 문항 YES ≥ 1개 ∧ Deal-killer 없음. 그 밖은 보류.**

기준값은 평가 결과를 보기 전에 이 문서로 고정하고, 결과를 보고 바꾸지 않는다. 기준값은 설정 파일에 두고 하드코딩하지 않는다.

- **1.10**: 동종 평균보다 10% 앞선다는 뜻이다. 가이드가 링크한 두 참고자료의 예시 배수 1.1205(Eqvista)·1.155(ACA 2019)보다 낮은 값으로 정한다. 원 방법에는 투자/보류 기준값이 없으므로 **설계 가정**이며, 1.00~1.20 민감도를 보고서에 공개한다(C.8, 보고서 4장).
- **창업자 YES ≥ 1**: 최대 비중(30%)이자 Bessemer 5 '창업자와 팀은 이 분야에서 믿을만한가?'를 근거 없이 넘기지 않는다.
- **Deal-killer**: C.2 의 K1~K3(인허가 미취득 · 특허·차별점 모두 반대 근거 · 공개 수치와 제3자 근거의 모순).
- **보류 유형**(보고서의 '왜 안 되는가'에 쓰는 이름표, 앞선 것 우선): Deal-killer > 창업자 근거 없음 > 정보 부족(미확인 60% 이상: '나쁜 회사'가 아니라 '공개 정보로는 알 수 없음') > 동종 대비 열위.
- 결과 값은 '투자'·'보류' 두 개뿐이다(가이드 '기준 점수 따라 투자 VS 보류').
- **가이드 역할 '종합 판단 (리스트, ROI 등)'은 두 해석을 모두 반영한다.** '리스트'는 **후보 리스트**(동종 기준 집단 안의 순위표, 보고서에 대상 순위와 상위 3곳)로도, **리스크**(Deal-killer·보고서 리스크 표)로도 읽을 수 있어 둘 다 보고서에 싣는다. ROI 는 C.7 에 둔다.

### C.5 Bessemer 10문 점검표 (보고서 4장)
| # | Bessemer 질문(가이드 원문) | 연결 문항 |
|---|---|---|
| 1 | 이 시장은 얼마나 큰가? | M1 |
| 2 | 제품이 시장의 실제 문제를 해결하는가? | M3, P1 |
| 3 | 고객이 실제로 이 제품에 비용을 지불할 이유가 있는가? | M4, R2 |
| 4 | 경쟁사 보다 뚜렷한 차별성이 있는가? | C2, P3, C1 |
| 5 | 창업자와 팀은 이 분야에서 믿을만한가? | F1, F2 |
| 6 | 초기 고객의 반응은 어떠한가? | R2, R3 |
| 7 | 수익 모델은 명확한가? | M4, R4 |
| 8 | 이 스타트업이 성공한다면, 정말 큰 기회가 될까? | M2 (ROI 는 참고치로 함께 표시, C.7) |
| 9 | 기술, 운영, 법률적 리스크는 무엇인가? | P4, D4 + Deal-killer |
| 10 | 이 창업자가 다음 10년을 이 분야에 쏟아부을 각오가 있는가? | F1 + F3 — 대리지표: 창업 전 같은 분야 경력 + 창업 후 이어진 마일스톤 |


- 표시 규칙: 연결 문항 중 NO 가 있으면 X, YES 가 있으면 O, 둘 다 없으면 '미확인'. 보고서 4장에 질문마다 한 줄로 싣는다.
- 결론은 Scorecard 결정 규칙(C.4)으로만 낸다. Bessemer 표는 투자자가 읽는 요약이며 결론에 영향을 주지 않는다.

### C.6 뒤집힘 조건과 실사 항목
보류 후보에는 '무엇이 확인되면 투자 검토가 가능한가'를, 투자 추천 후보에는 '투자 전에 무엇을 확인해야 하는가'를 붙인다. 두 목록 모두 투자 판단 단계에서 판정 결과로 계산한다.

**뒤집힘 조건과 실사 항목의 산출 규칙**

| 대상 | 산출물 | 고르는 규칙 | 예외 처리 |
|---|---|---|---|
| 보류 후보 | 뒤집힘 조건: 확인되면 M 이 얼마가 되는지 | 미확인 문항 중 YES 가 될 때 M 이 가장 크게 오르는 순서로 최대 3개 | 창업자 요건 미충족이면 창업자 문항 우선, Deal-killer 면 'Kx 해소 필요' |
| 투자 추천 후보 | 실사 조건: 회사에 직접 확인할 질문 | 결론에 영향이 큰 미확인·NO 문항 3~5개 | 문항마다 평가표에 정의한 실사 문구 사용 |

- 뒤집힘 조건은 교수님이 요구한 '왜 안 되는지'에 대한 답이자 재평가 조건이다.
- 실사 문구는 코퍼스 문서 AgFunder(2026) p.60 의 VC 경고 신호('pilots presented as revenue', 매출총이익률·투자 회수기간·이탈률)에 맞춘다: 유료 계약서, 농가 투자 회수기간, 재계약·이탈률, 매출총이익률, 밸류에이션·지분율.

### C.7 ROI 참고치 (점수·결정에 넣지 않음)
ROI 는 보고서 4장에 참고치로만 싣고 점수·결정에는 넣지 않는다. 비상장 초기 기업은 밸류에이션이 거의 공개되지 않아, 가정에 기댄 숫자가 결론을 좌우하면 안 되기 때문이다. 가이드의 투자 판단 역할 'ROI 등'과 스타트업 특징 '10배 성장', 'M&A, IPO 등'에 대응한다.

**ROI 참고치 계산 항목**

| 항목 | 계산 | 근거·표기 |
|---|---|---|
| (a) 진입 가격 | 이번 라운드 금액 ↔ 단계별 중앙 투자금 | AgFunder(2026) p.13(코퍼스): 2025년 Seed $1M · Series A $7M · Series B $14M · Series C $14M. Pre 단계는 앞 단계 값(가정) |
| (b) 필요 Exit 가치 (VC Method) | 추정 post-money × 목표 10배 | post-money = 라운드 금액 ÷ 가정 지분율(10~20%). '가정'으로 표기, 후속 라운드 희석 미반영 |
| 환율 | 원화 라운드 금액 → 달러 | 1달러 = 1,400원(가정) |
| 금액 비공개 | 계산하지 않음 | '산정 불가'로 두고 실사 항목(D1·D3)으로 넘김 |

### C.8 기준값 검증 계획과 민감도
기준 1.10 과 결정 규칙(C.4)은 구현 전 설계 단계에서 고정하고, 결과를 보고 바꾸지 않는다. 구현 후에는 기준을 조정하는 대신 아래 방법으로 척도가 뜻대로 작동하는지 점검하고, 그 결과를 보고서에 함께 싣는다.

**기준값 검증 계획**

| 점검 | 방법 | 확인 기준·보고 |
|---|---|---|
| 동종 기준 집단 | 적격성 관문을 통과한 후보(최대 10곳)를 같은 절차로 판정해 문항별 동종 평균 신호를 고정. 평가 대상은 자기 제외 평균, 집단이 5곳 미만이면 평균 0 | 집단 규모와 단계·지역 구성을 보고서에 표기 |
| 척도(양성 대조) | 실제로 투자를 유치한 기업을 같은 방식으로 평가 | 동종 평균 대비 약 100 근처 ('투자 받은 평균 기업 = 100') |
| 기준 민감도 | 기준 1.00·1.05·1.10·1.15·1.20 별 투자 추천 수 | 보고서 4장에 기준 1.10 결과와 함께 게재 |
| 보류 사유 | 보류 후보마다 보류 유형(C.4)과 뒤집힘 조건(C.6) 표기 | '정보 부족'(확인되지 않음)과 '동종 대비 열위'(확인된 약점)를 구분 |

- **한계 1 — 상대 평가**: 기준 집단 전체의 질이 낮으면 상대적으로 나은 기업이 추천될 수 있다. 관문(실제 투자 유치 확인), 창업자 근거 요건, Deal-killer, '실사 조건부' 추천으로 막는다.
- **한계 2 — 기준 집단은 근사**: 원 방법은 같은 지역·같은 단계의 투자 유치 기업과 비교하지만, 기준 집단은 한 번의 평가에서 모으는 적격 후보이므로 단계(Seed~Series C)와 지역(국내·해외)이 섞일 수 있다. 두 한계는 보고서 한계점 장에 적는다.

## D. 그래프 설계

### D.1 State 설계
State 는 데이터를 담는 그릇이 아니라 **에이전트 사이의 인터페이스 규격**이다(교수님 표현). 설계 규칙은 세 가지다. ① 키마다 쓰는 노드와 읽는 노드를 정한다. ② 노드는 **바뀐 키만** 딕셔너리로 반환한다. ③ 다음 에이전트가 이어 써야 하는 키에만 Reducer 를 붙이고, 나머지는 덮어쓴다.

**에이전트 간 데이터 흐름**

| 보내는 노드 | 키 | 받는 노드 | 용도 |
|---|---|---|---|
| 탐색 | `current` | 창업자 · 투자 판단 | 단계·라운드 금액·대표·설립일·국민연금 → 창업 시점 t0, D1·ROI |
| 창업자 · 기술 요약 · 시장성 | 근거 id | 뒤 분석 에이전트 | 판정 근거 풀 공유(예: 시장성의 수요 문항이 기술 요약이 모은 회사 기사를 읽음) |
| 기술 요약 | `tech.claims` | 경쟁사 비교 | 차별점 주장 검증 |
| 분석 에이전트 4개 | 기준 판정 | 투자 판단 | 6개 기준 종합 |
| 투자 판단 | `evaluations` | 보고서 | 후보별 누적 → A안·B안 |
| 모든 에이전트 | `registry` | 보고서 | REFERENCE |

키 22개. Reducer 는 `operator.add`(이어 붙이기), `merge_dict`(키 단위 병합), `add_unique`(중복 없이 추가) 세 가지이고, 표시가 없는 키는 덮어쓴다. discover 뒤 괄호(발굴·관문·선택·소진)는 탐색 에이전트의 내부 단계다.

**State 키 정의 ① 공통·탐색 키**

| 키 | 타입 · Reducer | 쓰는 노드 | 읽는 노드 | 설명 |
|---|---|---|---|---|
| `domain` | str | 시작 입력 | discover | 평가 도메인(AgTech) |
| `run_date` | str | 시작 입력 | 전 노드 | 평가 기준일 — 24개월 판정·조회일의 기준 |
| `registry` | dict<br>`merge_dict` | 모든 에이전트 | 모든 에이전트 · report | 근거 저장소 {근거 id: 출처 정보}. id = URL·문서 해시(W/D). REFERENCE 의 재료 |
| `discovery_rounds` | int | <span style="white-space:nowrap">discover(발굴)</span> | discover(진입 판단) | 발굴 라운드 수(최대 2) |
| `raw_candidates` | list[dict] | <span style="white-space:nowrap">discover(발굴)</span> | discover(관문) | 이번 라운드에 발굴한 후보 |
| `seen` | list[str]<br>`add_unique` | <span style="white-space:nowrap">discover(발굴)</span> | discover(발굴) | 이미 다룬 후보 이름 — '다른 스타트업'을 보장 |
| `screened` | list[dict]<br>`operator.add` | <span style="white-space:nowrap">discover(관문)</span> | report | 관문 판정 기록(통과·탈락 사유) — 보고서의 탐색 경과 표 |
| `queue` | list[dict] | <span style="white-space:nowrap">discover(관문·선택)</span> | discover | 적격 후보 대기열(국내·해외 몫을 섞음) |
| `current` | dict / None | <span style="white-space:nowrap">discover(선택·소진)</span> | founder · tech · market · competition · decide · 라우터 | 평가 대상 프로필(단계·라운드·금액·대표·설립일·국민연금). None = 후보 소진 |
| `iterations` | int | <span style="white-space:nowrap">discover(선택)</span> | 라우터 · report | 심층 평가한 후보 수(최대 10) |

**State 키 정의 ② 분석·판단 키**

| 키 | 타입 · Reducer | 쓰는 노드 | 읽는 노드 | 설명 |
|---|---|---|---|---|
| `founder` | dict | founder | tech · market · competition(근거 풀) · decide | 창업 시점 t0, 인물(창업 전 경력), 날짜 있는 마일스톤, 고용 추이, 창업자 기준 판정 — 새 후보를 꺼낼 때 비움 |
| `tech` | dict | tech | market(근거 풀) · competition(차별점 주장) · decide | 제품·핵심 기술·장점/단점·차별점 주장·기술 기준선, 제품/기술력 판정 — 새 후보를 꺼낼 때 비움 |
| `market` | dict | market | competition(근거 풀) · decide | 시장 규모(수치·연도·출처)·성장·수요·정책, 시장성 판정 — 새 후보를 꺼낼 때 비움 |
| `competition` | dict | competition | decide | 경쟁사 비교표·차별점 검증 결과, 경쟁 우위 판정 — 새 후보를 꺼낼 때 비움 |
| `market_cache` | dict<br>`merge_dict` | market | market | 세부 분야별 시장 분석 재사용(같은 분야 후보의 비용 절감) |
| `scorecard` | dict | decide | 없음(report 는 evaluations 안의 사본을 읽음) | 6개 기준 비교율·배수 M·결정·보류 유형·뒤집힘 조건·실사 항목·ROI·민감도·순위 — 새 후보를 꺼낼 때 비움 |
| `decision` | '투자' / '보류' | decide | 라우터 | 이번 후보의 결정 |

**State 키 정의 ③ 누적·종료·보고 키**

| 키 | 타입 · Reducer | 쓰는 노드 | 읽는 노드 | 설명 |
|---|---|---|---|---|
| `evaluations` | list[dict]<br>`operator.add` | decide | report | 후보별 평가 누적 — 보류 사유·순위 보고서의 재료 |
| `end_reason` | str | <span style="white-space:nowrap">discover(소진)</span> · decide | report | 종료 사유 invest_found / max_evaluations / exhausted / no_eligible |
| `report` | dict | report | 실행 기록 | 보고서 모드·파일·쪽수·형식 검사 결과 |
| `rag_traces` | list[dict]<br>`operator.add` | discover · tech · market | 실행 기록 | RAG 경로 기록(도구 선택·재작성·웹 보완·답변 점검 결과) |
| `log` | list[str]<br>`operator.add` | 전 노드 | 실행 기록 | 분기 이유가 들어간 진행 기록 |



### D.2 메인 그래프 (Workflow · Branch · Loop)
메인 그래프는 가이드 Graph(안)의 순차 흐름 **정보 수집(탐색) → 분석(창업자·기술·시장·경쟁) → 평가(투자 판단) → 보고서**를 그대로 따르고, 창업자 평가 노드 하나만 더한다(B.1).

```mermaid
graph TD
  S(("START"))
  discover["🔍 스타트업 탐색<br/>발굴 → 적격성 관문 → 다음 후보 1곳"]
  founder["👤 창업자 평가<br/>창업자 30%"]
  tech["🗜️ 기술 요약<br/>제품/기술력 15% · Agentic RAG"]
  market["📊 시장성 평가<br/>시장성 25% · Agentic RAG"]
  competition["🥊 경쟁사 비교<br/>경쟁 우위 10%"]
  decide["🧮 투자 판단<br/>실적·투자조건 20% · 동종 대비 배수"]
  report["📝 보고서 생성<br/>A안 투자 · B안 모두 보류 · C안 후보 없음"]
  T(("END"))
  S --> discover
  discover -->|"평가 대상 있음"| founder
  discover -->|"후보 소진 · 적격 후보 없음"| report
  founder --> tech
  tech --> market
  market --> competition
  competition --> decide
  decide -->|"투자 추천 또는 평가 상한 도달"| report
  decide -->|"보류 → 다른 스타트업"| discover
  report --> T
```

**분기 조건과 종료 사유**

| 분기 지점 | 조건 | 다음 노드 | 종료 사유 |
|---|---|---|---|
| 탐색 뒤 | 평가 대상 있음 | 창업자 평가 | — |
| 탐색 뒤 | 후보 소진(대기열 없음 ∧ 발굴 2라운드 소진) | 보고서 | 평가 0곳 = no_eligible(C안), 그 밖 = exhausted(B안) |
| 투자 판단 뒤 | **투자 추천** | 보고서(A안) | invest_found |
| 투자 판단 뒤 | 보류 ∧ 평가 10곳 도달 | 보고서(B안, 미평가 적격 후보 명시) | max_evaluations |
| 투자 판단 뒤 | **보류**(평가 10곳 미만) | 탐색(다른 스타트업) | — |

- **보정 모드**(동종 기준 집단 생성)도 같은 그래프를 쓴다. 투자 추천이 나와도 멈추지 않고 평가 상한 또는 후보 소진까지 평가한 뒤, 같은 간선으로 보고서 노드를 거쳐 끝난다. 이 모드의 보고서 노드는 보고서를 만들지 않으므로 간선은 그림과 같다.
- 구현 시 설계 그림의 노드·간선과 코드의 노드·간선이 1:1 인지, State 키가 표의 정의와 같은지 검증한다.

**반복 상한**

| 반복(Loop) | 상한 | 근거 |
|---|---|---|
| 후보 루프(보류 → 탐색) | 심층 평가 10곳 | 반 공용 API 키 비용 · 루프마다 최대 반복 횟수를 둔다 |
| 발굴 라운드 | 2 | 표현을 바꿔 한 번 더 |
| RAG 도구 선택 | 질문당 1회 | — |
| RAG 질의 재작성 | 2 | 재작성 뒤에도 부족하면 웹 보완 |
| RAG 답변 재생성 | 1 | 검색은 충분한데 답이 근거를 벗어나면 답변만 다시 |
| 보고서 재작성 | 2 | 5쪽 초과 시 조판 밀도 조정 → 2/3 축약 |
| 안전장치 | recursion_limit 메인 100 · RAG 25 | 모든 루프에 명확한 종료 조건 |

**협업 패턴**

- 'Graph(안) 순차 파이프라인 + 조건부 루프'다. 최종 판정의 책임은 투자 판단 노드에 있다.
- 관리자 에이전트가 하위 결과를 받아 재작업을 지시하는 구조가 아니므로 Supervisor 패턴으로 부르지 않는다.
- 병렬 실행은 쓰지 않는다. 경쟁사 비교가 `tech.claims` 를, 뒤 에이전트가 앞 에이전트의 근거 풀을 받아 쓰는 순서 의존이 있기 때문이다.

### D.3 탐색 에이전트 내부 흐름
탐색 에이전트는 대기열을 먼저 보고, 비어 있을 때만 발굴한다. 내부는 발굴 → 적격성 관문 → 다음 후보 선택의 3단계이며, 발굴 2라운드 뒤에도 적격 후보가 없으면 후보 소진으로 보고서 노드에 넘긴다.

```mermaid
graph LR
  I(["탐색 진입"]) --> Q{"대기열에 적격 후보가 있나"}
  Q -->|있음| P["다음 후보 선택<br/>1곳 꺼냄 · 후보별 결과 키 비움"]
  Q -->|"없음 · 발굴 2라운드 미만"| C["발굴<br/>채널 8개 · 교차 신호"]
  Q -->|"없음 · 라운드 소진"| X["후보 소진<br/>current 없음 · 종료 사유 기록"]
  C --> V["적격성 관문<br/>G1~G6 · 확인 못 하면 탈락"]
  V --> Q
  P --> O(["평가 대상 1곳 → 창업자 평가"])
  X --> Z(["보고서 생성으로"])
```

- 선택 단계는 후보 1곳을 꺼내면서 후보별 결과 키(`founder`·`tech`·`market`·`competition`·`scorecard`)를 비운다.
- 누적 키(`screened`·`log`·`rag_traces`)는 **새 기록만** 돌려주고, 메인 State 의 Reducer 가 중복 없이 이어 붙인다.
- 발굴·관문 결과는 재현용 캐시로 남긴다.

### D.4 Agentic RAG 서브그래프
RAG 는 한 번 도는 파이프라인이 아니라 **에이전트가 상황에 맞게 고르는 목적성 있는 도구**로 둔다. 검색 여부와 검색처(문서·웹)는 에이전트가 판단하고, 수업의 Agentic RAG 흐름(검색 선택 → 검색 → 관련성 평가 → 답변 → 환각 점검 → 질문 적합성 점검)대로 단계마다 점검한다.

**호출 위치**

| 에이전트 | 쓰는 방식 |
|---|---|
| 기술 요약 | 분야 기술 기준선 1문항 |
| 시장성 | 시장 질문을 하위 질문 3~6개로 분해(투자 사이클 질문 포함)하고, 하위 질문마다 호출 |
| 탐색 | 기업명 추출이 목적이므로 **교정형 경로(retrieve → grade → rewrite → web)만** 쓰고 답변은 생성하지 않음 |

- 에이전트 호출에서는 '검색 없이 직접 답하기'를 쓰지 않는다. 수치 질문이 근거 없이 답해지는 것을 막기 위해서다.
- 질의 확장(expansion)은 쓰지 않고 재작성과 분해만 쓴다. 경로(도구 선택·재작성·웹 보완·재생성)는 `rag_traces` 에 쌓아 실행 기록으로 남긴다.

#### Agentic RAG 서브그래프 흐름

```mermaid
graph TD
  Q(["질문 · 목적"]) --> AG["agent: LLM 이 문서 검색·웹 검색 중 고름<br/>수치·정책·기술 기준선은 문서 우선"]
  AG -->|문서 검색| RT["retrieve<br/>BM25 0.4 + KURE-v1 0.6 · 후보 8"]
  AG -->|웹 검색| WB["web<br/>웹 검색 · 최근 1년 우선"]
  RT --> GR["grade<br/>조각별 관련 O/X"]
  GR -->|"관련 3개 이상 · 앞 4개"| GN["generate<br/>인용 달린 답변"]
  GR -->|"부족 · 재작성 2회 미만"| RW["rewrite<br/>질의 재작성"]
  GR -->|"부족 · 재작성 소진"| WB
  RW --> RT
  WB --> GN
  GN --> CK["check<br/>수치 대조 + LLM 이진 점검"]
  CK -->|grounded| FN(["finish<br/>답변 · 근거 id · 상태"])
  CK -->|"not_grounded · 재생성 1회 미만"| GN
  CK -->|"not_useful · 재작성 2회 미만"| RW
  CK -->|"상한 도달"| FN
```

**서브그래프 노드 역할**

| 노드 | 하는 일 |
|---|---|
| `agent` | LLM 이 **문서 검색·웹 검색 중 고른다**(둘 다 가능). 시장 수치·정책·기술 기준선은 문서 우선, 개별 기업·최근 사건은 웹(최근 1년 우선). 선택과 이유를 기록한다 |
| `retrieve` | Kiwi BM25 0.4 + KURE-v1 0.6 (RRF), 검색기마다 후보 8개 |
| `grade` | Judge LLM 이 조각마다 관련 O/X(이진). 관련 조각은 검색 순위대로 앞 4개만 쓴다 |
| `rewrite` | 관련 조각이 3개 미만이면 질의 재작성(최대 2회) |
| `web` | 재작성 뒤에도 부족하면 웹 검색으로 보완(Corrective RAG) |
| `generate` | 남은 근거만으로 짧게 답한다. 문장마다 근거 id, 수치에는 기준 연도·기관. 근거가 없으면 '근거에서 확인되지 않음'(채점 항목 '컨텍스트 활용') |
| `check` | 규칙 대조(답변 속 수치가 인용 근거에 있나) 뒤 Judge 가 이진 두 문항(근거로 뒷받침되나 / 질문에 답했나)을 판정. **grounded** → 종료, **not_grounded** → 검색은 두고 답변만 재생성(최대 1회), **not_useful** → 질의 재작성부터. 상한에 닿으면 점검한 답 중 가장 나은 것(grounded > not_useful > not_grounded)을 내어, 재생성한 답이 더 나빠져도 앞의 답을 잃지 않게 한다 |
| `finish` | 실제로 인용된 근거만 저장소에 남기고 {답변, 근거 id, 상태, 경로 기록}을 돌려준다 |

## E. 투자 보고서 목차 (초안)
목차는 그래프 종료 사유(D.2)에 따라 A·B·C안 중 하나로 정하고, 세 안 모두 가이드 문구 그대로 **투자자에게 기업의 성장 가능성과 위험 요소를 전달**하는 데 맞춘다.

**목차 선택 규칙**

| 안 | 쓰는 경우 | 종료 사유 | 분량 |
|---|---|---|---|
| A안 | 투자 추천 후보가 나옴 | invest_found | 5쪽 이내 |
| B안 | 평가한 후보가 모두 보류 | exhausted · max_evaluations | 5쪽 이내 |
| C안 | 적격 후보가 하나도 없음 | no_eligible | 1~2쪽 |

**공통 규칙**

- 맨 앞 **SUMMARY**, 맨 뒤 **REFERENCE**, 전체 **5쪽 이내**.
- A안 본문은 가이드 '보고서 주요 내용' 5항목(사업 아이디어·사업 리스크·시장 규모·팀의 구성·한계점)과 1:1 인 **5개 장**이다. '5장 이내'를 쪽으로 읽어도 장으로 읽어도 지킨다.
- 장마다 첫 줄은 굵은 결론 한 문장이다(한 장 한 메시지).
- 표·점수·순위·ROI·결론 줄은 State 값으로 채우고, LLM 은 문장만 쓴다. 보고서 노드가 읽는 키는 `evaluations`·`screened`·`iterations`·`end_reason`·`registry` 다(D.1).

**REFERENCE 표기** (가이드 형식 그대로)

- 기관 보고서: 발행기관(YYYY). 보고서명. URL
- 학술 논문: 저자(YYYY). 논문제목. 학술지명, 권(호), 페이지.
- 웹페이지: 기관명 또는 작성자(YYYY-MM-DD). 제목. 사이트명, URL
- 본문에 실제로 인용한 자료만 싣고, 위 세 유형으로 묶는다. 목록 줄 끝에 다른 주석을 붙이지 않는다.
- 게시일이 없는 웹페이지는 조회일을 적고, 그 사실은 REFERENCE 가 아니라 **한계점** 장에 적는다.
- 포털에 다시 실린 기사는 원 언론사로 적고 한 번만 싣는다.

**보고서 자동 검사 — 실패 시 이유를 붙여 재작성(최대 2회)**

| 영역 | 통과 기준 |
|---|---|
| 분량 | 5쪽 이하 · SUMMARY 높이 ≤ A4 50% |
| 구성 | 첫 장 SUMMARY · 끝 장 REFERENCE · 가이드 필수 5항목 존재 · '(→n장)'이 실제 장을 가리킴 |
| 문장 | 금지어(개요 문장) 0건 · '앞선다'·'상용' 같은 단정이 판정과 일치 · 가정 수치에 '가정' 표기 |
| 결론 | 결론 줄 = 평가표 결정 |
| 출처 | 본문 인용 = REFERENCE 목록 · REFERENCE 3유형 형식 |

**SUMMARY 형식 — 반 장 보고**: **상황 → 결론 → 근거(→n장) → 요청('~할까요?')**. 교수님이 말한 '상황 말하고, 결론 말하고, 할까요 말까요' 순서다.

- A4 **절반 이내**. 렌더링한 뒤 높이를 재어 검사한다.
- **개요 문장 금지**. '이 보고서는 …'처럼 문서를 소개하는 문장 없이 상황부터 쓴다. 금지어 목록으로 자동 검사한다.
- **결론 줄은 LLM 이 쓰지 않는다.** 평가표 결정에서 그대로 만들어 결정과 늘 같게 한다. 근거·리스크 줄 끝의 '(→n장)'도 장 번호에서 자동으로 붙인다.

**SUMMARY 구성 — A안 · B안**

| 순서 | A안 (투자 추천) | B안 (모두 보류) |
|---|---|---|
| ① 상황 | 후보 N곳 발굴 → 관문 통과 k곳(모두 투자 유치 확인) → m번째 평가 | 발굴 N → 적격 m → 평가 n곳 |
| ② 결론 | '{회사} 투자 추천(실사 조건부) — 동종 평균 대비 {M×100}(평균 100, 기준 110), 동종 n곳 중 r위' | '투자 추천 없음 — 평가한 n곳 모두 보류(적격 m곳 중 비용 상한 n곳 평가), 최고점 {회사} {M×100}(기준 110)' |
| ③ 근거 | 기술·차별성(→1장) · 시장(→2장) · 팀(→3장) | 공통 원인(→4장) |
| ④ 리스크·조건 | 리스크·실사 조건(→4장) | 가장 가까운 후보의 뒤집힘 조건(→2장) |
| ⑤ 요청 | '실사 확인 항목 k개를 조건으로 투자심의 상정을 진행할까요?' | '{회사} 실사 착수 또는 미평가 적격 j곳 추가 평가를 승인할까요?' |

- 적격 후보를 모두 평가한 경우(후보 소진) B안 결론의 괄호는 '(적격 m곳 모두 평가)'로 쓴다.

**A안 — 투자 추천 대상이 있을 때**

| 장 (분량) | 담는 내용 | 재료 |
|---|---|---|
| SUMMARY (½쪽) | 위 SUMMARY 구성의 A안 | 전체 |
| 1. 사업 아이디어(핵심 컨셉)·기술·경쟁 차별성 (1쪽) | 해결하는 문제·제품·수익 방식, 핵심 기술 장점/단점 표(홈페이지 내용은 '회사 주장' 표시), 분야 기술 기준선 대비 위치, 경쟁사 비교표, 제3자로 확인된 차별점과 회사 주장 구분 | 기술 요약 · 경쟁사 비교 |
| 2. 시장 규모와 성장성 (0.6쪽) | 세부 시장 규모(기준 연도·추정 기관), 성장률(지난 전망은 발표 연도 표기), 수요·지불 의향, 정책, 투자 조정 국면 | 시장성 |
| 3. 팀의 구성(핵심 창업자·기술 역량) (0.5쪽) | 창업 시점 t0 와 근거, 창업 전 경력, 창업 후 날짜 있는 마일스톤, 고용 추이(국민연금) | 창업자 평가 |
| 4. 투자 판단과 사업 리스크 (1.2쪽) | 6개 기준 표(비중·YES/NO/미확인·동종 평균 대비 %), 배수·기준·기준 집단, 민감도 한 줄, Bessemer 10문 한 줄, 동종 순위 상위 3곳 / 리스크 표(시장·기술·규제·경쟁, 근거·완화), 실사 조건 3~5개, ROI(가정 표시) | 투자 판단 · 전 에이전트 |
| 5. 한계점 (0.3쪽) | 공개 정보 한계, 가정(지분율·환율·배수), 검색 실패, Judge 모델 한계, 상대 평가와 기준 집단 근사, 미평가 후보, 게시일 없는 웹페이지의 조회일 대체 | 실행 기록 |
| REFERENCE (0.7쪽) | 본문에 실제로 인용한 자료만, 기관 보고서 / 학술 논문 / 웹페이지로 묶음 | 근거 저장소 |

모두 보류이면 교수님 말대로 후보마다 **'왜 안 되는지'**, 그 이유들로 보고서를 구성한다. 가이드 필수 항목은 3장(최고점 후보)에서 채운다.

**B안 — 평가한 후보가 모두 보류일 때**

| 장 | 담는 내용 |
|---|---|
| SUMMARY | 위 SUMMARY 구성의 B안 |
| 1. 후보 풀과 선정 과정 | 발굴 → 관문 → 적격 → 심층 평가 수(국내/해외), 탈락 사유, 적격이지만 평가하지 못한 후보와 이유 |
| 2. 후보별 보류 사유 | 후보마다: 사업 아이디어 한 줄 / 팀(대표·t0) / **왜 안 되는지**(보류 유형·M·결정적 문항과 원문 인용) / **뒤집힘 조건**(무엇이 확인되면 M 이 얼마가 되는지) |
| 3. 최고점 후보 상세 | 사업 아이디어·수익 방식, 시장 규모와 성장성, 기술력과 팀, 경쟁 구도, 사업 리스크(시장·기술·규제·경쟁) |
| 4. 투자 판단 요약 | 후보별 6개 기준 비교율·M·보류 유형 표, 기준 집단·민감도, 공통 원인 |
| 5. 한계점 | A안과 같음 |
| REFERENCE | A안과 같음 |

**C안 — 적격 후보가 하나도 없을 때**: SUMMARY(상황·결론 '적격 후보 없음'·요청) · 1. 탐색 경과와 탈락 사유 표 · 2. 한계점 · REFERENCE. 1~2쪽.
